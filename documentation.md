# Документация информационной системы «AtmoTeam Social Network»

---

## 1. Введение

Настоящий документ представляет собой полное описание информационной системы **«AtmoTeam Social Network»** — современной социальной сети, разработанной на базе фреймворка **Yii Framework 2** с использованием языка **PHP 7.4+** и СУБД **MySQL 5.7+ / MariaDB**.

Система предоставляет пользователям широкий спектр возможностей для общения, обмена контентом и социального взаимодействия: создание публикаций с изображениями и опросами, система подписок и подписчиков, личные сообщения, истории (stories) с 24-часовым сроком хранения, лайки, комментарии, репосты, уведомления в реальном времени, поиск пользователей и контента, а также полнофункциональную панель администратора.

Проект реализован как монолитное веб-приложение с использованием архитектурного паттерна **MVC** (Model-View-Controller), предоставляющее как серверный рендеринг страниц, так и RESTful API для асинхронных операций на клиенте. Фронтенд построен на чистом JavaScript (Vanilla JS) с использованием современных возможностей CSS3 (Flexbox, Grid, CSS Custom Properties) и технологий Progressive Web App (PWA).

## 2. Техническое задание и эскизный проект

### 2.1. Характеристика предметной области и пользователей

**Предметная область:** Социальные сети и онлайн-коммуникации.

**Целевая аудитория:**
- **Обычные пользователи** — физические лица, заинтересованные в общении, обмене контентом (текстовые посты, изображения, опросы), подписке на других пользователей, получении уведомлений о активности.
- **Администраторы** — лица, ответственные за модерацию контента, управление пользователями (блокировка, удаление), просмотр статистики и аналитики системы.

**Потребности пользователей:**
1. Регистрация и аутентификация в системе.
2. Создание и редактирование личного профиля (аватар, биография, настройки приватности).
3. Публикация контента (текстовые посты, изображения, опросы).
4. Взаимодействие с контентом других пользователей (лайки, комментарии, репосты, сохранение).
5. Коммуникация через личные сообщения.
6. Публикация историй с 24-часовым сроком жизни.
7. Поиск пользователей и контента.
8. Настройка ленты новостей (подписки, блокировки).
9. Управление уведомлениями.
10. Модерация и администрирование системы.

### 2.2. Постановка задачи и общие требования к функционалу сайта

**Цель разработки:** Создание полнофункциональной социальной сети, обеспечивающей все основные потребности пользователей в онлайн-коммуникации и обмене контентом.

**Задачи:**
1. Разработать систему аутентификации и управления пользователями.
2. Реализовать функционал создания и отображения публикаций с поддержкой изображений и опросов.
3. Реализовать систему социального взаимодействия (подписки, лайки, комментарии, репосты).
4. Разработать систему личных сообщений.
5. Реализовать функционал историй (stories).
6. Разработать систему уведомлений.
7. Реализовать поиск по пользователям и контенту.
8. Разработать панель администратора для модерации и управления.

11. Обеспечить производительность и кэширование данных.

#### 2.4.1. Требования к производительности
- **NFR-01:** Время загрузки страницы не должно превышать 2 секунд при нормальной нагрузке.
- **NFR-02:** Кэширование данных с использованием FileCache для снижения нагрузки на БД.
- **NFR-03:** Rate limiting для API-запросов для предотвращения злоупотреблений.
- **NFR-04:** Бесконечная прокрутка с подгрузкой постов порциями (limit/offset).
- **NFR-05:** Оптимизация изображений при загрузке.

#### 2.4.2. Требования к безопасности
- **NFR-06:** CSRF-защита для всех форм и AJAX-запросов.
- **NFR-07:** XSS-защита через экранирование вывода.
- **NFR-08:** Защита от SQL-инъекций через подготовленные запросы (ActiveRecord).
- **NFR-09:** Безопасное хранение паролей (password_hash с PASSWORD_DEFAULT).
- **NFR-10:** RBAC (Role-Based Access Control) для разграничения прав.
- **NFR-11:** Валидация всех входных данных на серверной стороне.
- **NFR-12:** Ограничение частоты запросов (rate limiting) для критичных эндпоинтов.

#### 2.4.3. Требования к надёжности
- **NFR-13:** Обработка ошибок с логированием (Yii logging).
- **NFR-14:** Транзакционность операций с БД (голосование в опросах, удаление контента).
- **NFR-15:** Graceful degradation при недоступности сети (Service Worker, offline page).

#### 2.4.4. Требования к совместимости
- **NFR-16:** Поддержка современных браузеров (Chrome, Firefox, Safari, Edge).
- **NFR-17:** Адаптивная вёрстка для устройств с различным разрешением экрана.
- **NFR-18:** Поддержка PWA (манифест, Service Worker).

#### 2.4.5. Требования к технологическому стеку

## 3. Архитектура разрабатываемой информационной системы

### 3.1. Обоснование выбора стека технологий

| Компонент | Технология | Обоснование |
|-----------|-----------|-------------|
| **Язык программирования** | PHP 7.4+ | Высокая производительность, строгая типизация, широкое распространение в веб-разработке, большое сообщество |
| **Фреймворк** | Yii Framework 2.0.45 | Высокая производительность, встроенный ActiveRecord, RBAC, кэширование, валидация, генерация кода (Gii), богатая экосистема расширений |
| **СУБД** | MySQL 5.7+ / MariaDB | Надёжность, производительность, поддержка транзакций, полнотекстовый поиск, широкое распространение |
| **Фронтенд** | Vanilla JavaScript | Отсутствие зависимости от тяжёлых фреймворков, полный контроль над кодом, минимальный размер бандла |
| **Стилизация** | CSS3 (Custom Properties, Flexbox, Grid) | Современные возможности CSS, темизация через CSS-переменные, адаптивность без медиа-запросов |
| **PWA** | Service Worker API | Офлайн-доступ, кэширование статики и API-ответов, улучшение пользовательского опыта |

| **Тестирование** | Codeception | Поддержка unit, functional, acceptance тестов, интеграция с Yii2 |
| **Почта** | Symfony Mailer | Современный почтовый клиент, поддержка различных транспортов |

**Почему Yii2, а не другие фреймворки:**
- Встроенный **ActiveRecord** с миграциями — быстрая работа с БД без ORM-оверхеда.
- **RBAC DbManager** — готовая система управления ролями и разрешениями.
- **Валидация моделей** — декларативное описание правил валидации.
- **Кэширование** — встроенная поддержка FileCache, MemCache, Redis.
- **URL Manager** — гибкая настройка ЧПУ (pretty URLs).
- **Gii** — генератор кода для ускорения разработки.
- **Высокая производительность** — один из самых быстрых PHP-фреймворков.

#### 3.2.2. Архитектурные решения

**1. MVC-архитектура:**
- **Model** — бизнес-логика и работа с данными (ActiveRecord).
- **View** — представления на PHP с HTML/CSS/JS.
- **Controller** — обработка запросов, координация Model и View.

**2. RESTful API:**
- Эндпоинты `/api/*` для асинхронных операций.
- Формат запросов/ответов — JSON.
- CSRF-токены для всех мутирующих запросов.

**3. Rate Limiting:**
- Кастомный компонент `RateLimiter` на основе FileCache.
- Различные лимиты для разных типов операций.
- HTTP-заголовки `X-RateLimit-*` для информирования клиента.

**4. RBAC:**
- Роли: `admin`, `user`, `guest`.
- Разрешения: `createPost`, `updatePost`, `deletePost`, `accessAdminPanel`.
- Иерархия: `admin` наследует все права `user`.

**5. Кэширование:**
- FileCache для данных статистики, популярных пользователей, активных пользователей.
- Кэширование результатов запросов с тегами для инвалидации.

**6. PWA:**
- Service Worker для кэширования статических файлов и API-ответов.
- Офлайн-страница при отсутствии сети.
- Фоновое обновление кэша.

## 4. Разработка и обоснование логотипа и элементов фирменного стиля

### 4.1. Логотип

Логотип **AtmoTeam** представляет собой стилизованное изображение, выполненное в векторном формате SVG. Файл логотипа: [`web/svg/logo.svg`](web/svg/logo.svg).

**Описание логотипа:**
- **Форма:** Стилизованное сердце, состоящее из двух половинок, символизирующее связь и эмоциональную близость между людьми — ключевую ценность социальной сети.
- **Цвета:** Градиент от фиолетового (`#8B5CF6`) к розовому (`#EC4899`), создающий современный и привлекательный вид.
- **Элементы:** Вокруг сердца расположены точки-узлы, соединённые линиями, что символизирует сетевую структуру и взаимосвязи между пользователями.
- **Шрифт:** Название «AtmoTeam» выполнено современным гротесковым шрифтом, подчёркивающим технологичность проекта.

**Обоснование:**
- Сердце — универсальный символ социальной сети, ассоциирующийся с «лайками» и эмоциональной связью.
- Фиолетово-розовый градиент — современная цветовая схема, популярная в современных социальных платформах.
- Сетевые узлы подчёркивают технологическую основу проекта и идею связей между людьми.

### 4.2. Цветовая схема

Система использует CSS Custom Properties для определения цветовой схемы с поддержкой тёмной и светлой темы.

**Светлая тема (по умолчанию):**
- Фон: `#f0f2f5` (светло-серый)
- Поверхности: `#ffffff` (белый)
- Основной текст: `#1a1a2e` (тёмно-синий)
- Вторичный текст: `#666` (серый)
- Акцентный цвет: `#8B5CF6` (фиолетовый)
- Границы: `#e0e0e0` (светло-серый)

**Тёмная тема:**
- Фон: `#0f0f23` (тёмно-синий)
- Поверхности: `#1a1a2e` (тёмно-синий)
- Основной текст: `#e0e0e0` (светло-серый)
- Вторичный текст: `#999` (серый)
- Акцентный цвет: `#a78bfa` (светло-фиолетовый)
- Границы: `#2d2d44` (тёмно-серый)

### 4.3. Типографика

- **Основной шрифт:** `-apple-system, BlinkMacSystemFont, 'Segoe UI', Roboto, sans-serif` (системные шрифты для максимальной производительности).
- **Размеры:** Используются `rem` для масштабируемости.
- **Межстрочный интервал:** `1.6` для основного текста.

#### 5.3.2. RBAC (Role-Based Access Control)

Система RBAC реализована через [`yii\rbac\DbManager`](config/web.php:49) с хранением данных в БД.

**Роли:**
| Роль | Описание | Наследование |
|------|----------|--------------|
| `guest` | Неавторизованный пользователь | — |
| `user` | Авторизованный пользователь | — |
| `admin` | Администратор | Наследует все права `user` |

**Разрешения:**
| Разрешение | Описание | Назначение |
|------------|----------|------------|
| `createPost` | Создание постов | `user`, `admin` |
| `updatePost` | Редактирование постов | `user`, `admin` |
| `deletePost` | Удаление постов | `user`, `admin` |
| `accessAdminPanel` | Доступ к админ-панели | `admin` |

**Иерархия:**
```
admin
  ├── accessAdminPanel
  ├── createPost (унаследовано от user)
  ├── updatePost (унаследовано от user)
  └── deletePost (унаследовано от user)

user
  ├── createPost
  ├── updatePost
  └── deletePost
```

**Миграция RBAC:** [`m240503_000007_setup_rbac.php`](migrations/m240503_000007_setup_rbac.php) создаёт таблицы RBAC, роли, разрешения и назначает роль `admin` пользователю с ID=1.

#### 5.3.3. Rate Limiting

Компонент [`RateLimiter`](components/RateLimiter.php) реализует ограничение частоты запросов на основе FileCache.

**Лимиты по умолчанию:**

| Метод | Ключ | Лимит | Окно | Назначение |
|-------|------|-------|------|------------|
| `checkPostLimit()` | `post` | 100 | 1 час | Создание постов |
| `checkCommentLimit()` | `comment` | 30 | 1 час | Комментарии |
| `checkLikeLimit()` | `like` | 100 | 1 час | Лайки |
| `checkFollowLimit()` | `follow` | 50 | 1 час | Подписки |
| `checkMessageLimit()` | `message` | 20 | 1 час | Сообщения |
| `checkVoteLimit()` | `vote` | 50 | 1 час | Голосования |
| `checkApiLimit()` | `api` | 1000 | 1 час | Общие API-запросы |
| `checkAuthLimit()` | `auth` | 5 | 15 минут | Попытки входа |
| `checkRegisterLimit()` | `register` | 3 | 1 час | Регистрации |
| `checkPasswordResetLimit()` | `password_reset` | 3 | 1 час | Сброс пароля |

**HTTP-заголовки ответа:**
- `X-RateLimit-Limit` — максимальное количество запросов
- `X-RateLimit-Remaining` — оставшееся количество запросов
- `X-RateLimit-Reset` — время сброса лимита (Unix timestamp)

#### 5.4.3. Адаптивный дизайн

Система использует адаптивную вёрстку на основе CSS Flexbox и Grid, обеспечивающую корректное отображение на устройствах с различным разрешением экрана.

**Ключевые особенности:**
- **Мобильная навигация:** На экранах менее 768px основное меню трансформируется в выдвижную панель (drawer).
- **Адаптивная сетка:** Посты и карточки пользователей перестраиваются в зависимости от ширины экрана.
- **Touch-friendly интерфейс:** Кнопки и интерактивные элементы имеют достаточный размер для касания.
- **Оптимизация изображений:** Изображения масштабируются под размер экрана.
- **Модальные окна:** Адаптируются под мобильные устройства (полноэкранный режим).

#### 5.4.4. Темизация (тёмная/светлая тема)

Реализована в файле [`theme.js`](web/js/theme.js):

- **Переключение темы:** Кнопка в интерфейсе переключает между тёмной и светлой темой.
- **Сохранение:** Выбор темы сохраняется в `localStorage`.
- **Системное предпочтение:** При первом посещении определяется через `prefers-color-scheme`.
- **CSS Custom Properties:** Все цвета заданы через CSS-переменные, что позволяет мгновенно переключать тему без перезагрузки страницы.
- **Preloader:** В `<head>` встроен скрипт, который применяет тему до загрузки страницы, предотвращая «flash of unstyled content» (FOUC).

#### 5.4.5. Валидация на клиенте

Валидация реализована на двух уровнях:

**Клиентская валидация (JavaScript):**
- Проверка длины контента поста (макс. 5000 символов) с счётчиком символов.
- Проверка длины комментария (макс. 1000 символов) с счётчиком символов.
- Проверка количества изображений (макс. 10).
- Проверка заполнения обязательных полей.
- Визуальная обратная связь (подсветка ошибок, уведомления).

**Серверная валидация (PHP):**
- Валидация через правила моделей Yii2 (`rules()`).
- Санитизация входных данных через `ApiValidator::sanitize()`.
- Проверка аутентификации и авторизации.
- Rate limiting для предотвращения злоупотреблений.
- Проверка типов файлов и размеров изображений.

#### 5.4.6. Progressive Web App (PWA)

Service Worker реализован в файле [`service-worker.js`](web/js/service-worker.js):

**Стратегии кэширования:**
- **Статические файлы (CSS, JS, шрифты):** Cache-first с фоновым обновлением.
- **API-запросы:** Network-first с fallback на кэш.
- **Офлайн-страница:** Возвращается при отсутствии сети.

**Кэшируемые ресурсы:**
- Статические: `/`, `/css/main.css`, `/js/common.js`, `/js/feed.js`, `/js/theme.js`, `/svg/logo.svg`
- API: `/api/posts`, `/api/notifications`, `/api/message/unread-count`

**Жизненный цикл:**
1. **Install:** Предзагрузка статических файлов.
2. **Activate:** Очистка старого кэша.
3. **Fetch:** Обработка запросов с соответствующей стратегией.
4. **Background Sync:** Фоновое обновление кэша при появлении сети.

## 6. Описание основных пользовательских сценариев

### 6.1. Регистрация и вход

1. Пользователь переходит на страницу `/register`.
2. Заполняет форму: имя пользователя, email, пароль.
3. Система проверяет уникальность имени и email, применяет rate limiting (3 регистрации в час).
4. После успешной регистрации пользователь перенаправляется на страницу входа.
5. Пользователь вводит имя пользователя и пароль на странице `/login`.
6. Система проверяет учётные данные, применяет rate limiting (5 попыток за 15 минут).
7. При успешном входе создаётся сессия, устанавливается cookie для auto-login.
8. Пользователь перенаправляется на ленту новостей.

### 6.2. Создание поста

1. Авторизованный пользователь на ленте нажимает кнопку «Создать пост».
2. Открывается форма создания поста.
3. Пользователь вводит текст (до 5000 символов), использует @упоминания и #хэштеги.
4. Пользователь может загрузить до 10 изображений (предпросмотр перед отправкой).
5. Пользователь может добавить опрос: вопрос и 2+ варианта ответа.
6. При нажатии «Опубликовать»:
   - Rate limiter проверяет лимит создания постов (100/час).
   - Данные отправляются через AJAX (POST `/api/post/create`).
   - Сервер валидирует данные, сохраняет пост, изображения, опрос.
   - Пост добавляется в ленту без перезагрузки страницы.

### 6.3. Взаимодействие с постами

**Лайк:**
1. Пользователь нажимает кнопку «Лайк» на посте.
2. Отправляется AJAX-запрос (POST `/api/post/like`).
3. Сервер проверяет rate limiting (100 лайков/час).
4. Если лайк уже есть — он удаляется (дизлайк), иначе — создаётся.
5. Создаётся уведомление автору поста.
6. Счётчик лайков обновляется без перезагрузки.

**Комментарий:**
1. Пользователь открывает пост (модальное окно или страница).
2. Вводит текст комментария (до 1000 символов).
3. Отправляется AJAX-запрос (POST `/api/comment/create`).
4. Rate limiter проверяет лимит (30 комментариев/час).
5. Комментарий добавляется в список без перезагрузки.
6. Автор поста получает уведомление.

**Репост:**
1. Пользователь нажимает кнопку «Репост».
2. Отправляется AJAX-запрос (POST `/api/repost`).
3. Создаётся новый пост, ссылающийся на оригинал (`original_post_id`).
4. Счётчик репостов оригинала увеличивается.

**Сохранение:**
1. Пользователь нажимает кнопку «Сохранить».
2. Пост добавляется в личную коллекцию сохранённых.
3. Доступно на странице `/profile/{id}/saved`.

### 6.4. Подписка и блокировка

**Подписка:**
1. Пользователь на странице профиля нажимает «Подписаться».
2. Rate limiter проверяет лимит (50 подписок/час).
3. Создаётся запись в таблице `follow`.
4. Целевой пользователь получает уведомление.

**Блокировка:**
1. Пользователь на странице профиля нажимает «Заблокировать».
2. Создаётся запись в таблице `block`.
3. Заблокированный пользователь не может:
   - Просматривать профиль блокировавшего.
   - Подписываться на блокировавшего.
   - Отправлять сообщения.
   - Комментировать посты.
4. Управление блокировками доступно на странице `/block/list`.

### 6.5. Личные сообщения

1. Пользователь переходит в раздел сообщений (`/message`).
2. Видит список диалогов с последними сообщениями.
3. Нажимает на диалог или начинает новый.
4. В диалоге отображается история переписки.
5. Пользователь вводит текст и/или выбирает изображение.
6. Rate limiter проверяет лимит (20 сообщений/час).
7. Сообщение отправляется через AJAX (POST `/api/message/send`).
8. Получатель видит счётчик непрочитанных сообщений.

### 6.6. Истории (Stories)

1. Пользователь переходит в раздел историй (`/story`).
2. Видит список историй от подписанных пользователей.
3. Нажимает на историю для просмотра.
4. История отображается в полноэкранном режиме.
5. Через 24 часа история автоматически удаляется.
6. Пользователь может создать свою историю, загрузив изображение.

### 6.7. Поиск

1. Пользователь вводит поисковый запрос в строку поиска.
2. Отправляется AJAX-запрос (GET `/api/search?q={query}`).
3. Сервер выполняет поиск по:
   - Именам пользователей (`LIKE %query%`).
   - Тексту постов (`LIKE %query%`).
   - Хэштегам (`#query`).
4. Результаты отображаются в реальном времени.

### 6.8. Администрирование

1. Администратор входит в систему с правами `admin`.
2. Переходит в админ-панель (`/admin`).
3. Видит статистику: количество пользователей, постов, комментариев.
4. Может просматривать списки пользователей, постов, комментариев.
5. Может блокировать/разблокировать пользователей.
6. Может удалять посты и комментарии.
7. Может снимать жалобы с комментариев.

## 7. Механизмы обеспечения безопасности и защиты данных

### 7.1. CSRF-защита

- Все формы содержат CSRF-токен, генерируемый Yii2.
- Все AJAX-запросы, изменяющие данные, отправляют CSRF-токен в заголовке `X-CSRF-Token`.
- Токен автоматически проверяется компонентом `yii\web\Request`.
- Функция `postWithCsrf()` в [`common.js`](web/js/common.js:8) автоматически добавляет CSRF-токен во все POST-запросы.

### 7.2. XSS-защита

- Все данные, выводимые в представлениях, экранируются через `Html::encode()` Yii2.
- На клиенте функция `escapeHtml()` в [`common.js`](web/js/common.js:2) экранирует HTML-сущности при вставке пользовательского контента через JavaScript.
- Компонент `ApiValidator::sanitize()` применяет `htmlspecialchars()` к входным данным.

### 7.3. SQL-инъекции

- Все запросы к БД выполняются через Yii2 ActiveRecord, который использует подготовленные запросы PDO.
- Параметры запросов передаются отдельно от SQL-кода.
- Прямые SQL-запросы не используются в коде приложения.

### 7.4. Безопасность паролей

- Пароли хешируются через `Yii::$app->security->generatePasswordHash()`, который использует `password_hash()` с алгоритмом `PASSWORD_DEFAULT` (bcrypt).
- Пароли никогда не хранятся в открытом виде.
- Валидация пароля через `Yii::$app->security->validatePassword()`.

### 7.5. RBAC (Role-Based Access Control)

- Доступ к админ-панели ограничен ролью `admin`.
- Доступ к созданию/редактированию/удалению постов ограничен разрешениями.
- Проверка прав выполняется через `Yii::$app->user->can()`.
- RBAC-проверки в [`behaviors()`](controllers/AdminController.php:19) контроллеров.

### 7.6. Rate Limiting

- Ограничение частоты запросов для всех критичных операций.
- Различные лимиты для разных типов операций (см. раздел 5.3.3).
- HTTP-заголовки `X-RateLimit-*` для информирования клиента.
- Сброс лимитов через заданные временные окна.

### 7.7. Валидация входных данных

- Все входные данные проходят валидацию через правила моделей Yii2 (`rules()`).
- API-эндпоинты используют `ApiValidator` для проверки и санитизации.
- Проверка типов и размеров загружаемых файлов.
- Проверка аутентификации и авторизации перед выполнением операций.

### 7.8. Приватность профилей

- Пользователи могут установить профиль как приватный.
- Контент приватного профиля виден только подписчикам.
- Проверка доступа в [`User::canViewProfile()`](models/User.php:194).

### 7.9. Безопасность сессий

- Cookie-based auto-login с использованием `auth_key`.
- Токен доступа (`access_token`) для API-аутентификации.
- Сессионные cookie с флагом HttpOnly.

### 7.10. Защита от ботов

- Rate limiting на регистрацию (3/час) и попытки входа (5/15 минут).
- Sitemap.xml для SEO без раскрытия чувствительных данных.

## 10. Заключение

В рамках данного проекта была разработана и реализована полнофункциональная социальная сеть **«AtmoTeam Social Network»** на базе фреймворка **Yii Framework 2** с использованием **PHP 7.4+** и **MySQL 5.7+ / MariaDB**.

### Основные результаты:

1. **Полный цикл разработки:** От проектирования архитектуры до реализации всех запланированных функций.

2. **Богатый функционал:** Система включает все основные возможности современных социальных сетей:
   - Аутентификация и управление профилями
   - Публикация контента (текст, изображения, опросы)
   - Социальное взаимодействие (лайки, комментарии, репосты, подписки)
   - Личные сообщения
   - Истории (stories)
   - Поиск пользователей и контента
   - Система уведомлений
   - Административная панель

3. **Безопасность:** Реализованы все необходимые механизмы защиты:
   - CSRF, XSS, SQL-инъекции
   - RBAC (ролевая модель доступа)
   - Rate limiting (ограничение частоты запросов)
   - Безопасное хранение паролей
   - Валидация всех входных данных

4. **Современный фронтенд:**
   - Адаптивный дизайн для всех устройств
   - Тёмная и светлая тема
   - PWA (Progressive Web App) с офлайн-доступом
   - Асинхронные операции без перезагрузки страницы

5. **Производительность:**
   - Кэширование данных
   - Бесконечная прокрутка
   - Оптимизация изображений
   - Docker-контейнеризация

6. **Масштабируемость:**
   - Модульная архитектура MVC
   - Чёткое разделение серверной и клиентской частей
   - RESTful API для всех операций
   - Готовая инфраструктура для тестирования
